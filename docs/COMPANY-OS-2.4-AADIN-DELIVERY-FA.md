# تحویل Company OS 2.4: بازطراحی منوی حسابداری بر اساس گزارش آدین

## دامنه و منشأ

منبع این نسخه دو فایل گزارش ارسالی کاربر است که در `docs/research/` بدون تغییر قرار دارند. **عنوان‌ها و طبقه‌بندی‌ها** از بخش ۳ تا ۷ گزارش استخراج شده‌اند؛ بخش ۸ به بعد «پیشنهاد Company OS» است، نه مشاهدهٔ عملی آدین.

این نسخه ۵ مقصد اصلی «پیشخوان، اشخاص، انبار، امور مالی، گزارشات»، ۱۸ گروه و ۶۷ مقصد فرعی با عنوان فارسی و انگلیسی در `frontend/lib/aadin-menu.ts` دارد. فایل `docs/research/aadin-menu-mapping.md` نگاشت دقیق کل عنوان‌ها و وضعیت پیاده‌سازی تک‌تک آن‌هاست.

## انجام شده

- صفحه حسابداری از قسمت کلی و سه‌تب قدیمی به یک فضای کاری با پنج مقصد، گروه‌های جمع‌شونده، جستجو و Breadcrumb تبدیل شد.
- رابط در دو زبان فارسی/انگلیسی و مطابق تم فعلی Next.js ساخته شد، با طرح واکنش‌گرا.
- دفتر حسابداری دوبل موجود (کدینگ، اسناد، تراز آزمایشی) حفظ شده و از بخش حسابداری و گزارش تراز قابل دسترس است.
- برای **۱۸ دسته فرم مقدماتی** (اشخاص، کالا، خدمت، پیش‌فاکتور، فروش، خرید، برگشت، دریافت، پرداخت، صندوق، حساب بانک، هزینه، چک، سفارش، کاتالوگ و هزینه فاکتور) ذخیرهٔ **پیش‌نویس غیرمالی** اضافه شد. قابلیت‌های ایجاد، فهرست، ویرایش و آرشیو دارد؛ از جدول افزوده `os_accounting_drafts` استفاده می‌کند. ایجاد و ویرایش به مجوز نوشتن بخش `finance` نیاز دارد، خواندن هم به مجوز خواندن. پیش‌نویس‌های هر سازمان جدا هستند و در Audit Log ثبت می‌شوند.
- محاسبهٔ دفتر از پیش‌نویس‌ها عمداً جداست: پیش‌نویس‌ها هیچ سند قطعی، موجودی، دریافت‌وپرداخت یا اثر حسابداری ثبت نمی‌کنند.
- برای صفحات با منطق مالی هنوز توسعه‌نیافته، پیام واضح نمایش داده می‌شود. دکمهٔ «ثبت قطعی» ساختگی وجود ندارد.

## انجام‌نشده / برای توسعه بعدی

ثبت واقعی خرید و فروش، صدور صورتحساب معتبر، تخصیص دریافت/پرداخت، انبار و کاردکس، بهای تمام‌شده، چک عملیاتی، بستن سال، برگشت با سند منشأ، مالیات قانونی، خروجی PDF/Excel داده‌دار و مهاجرت آدین **در این نسخه پیاده‌سازی نشده‌اند**. افزودن عنوان در منو به معنی وجود موتور آن عملیات نیست. قواعد مالیاتی، دقت پول، زمان ثبت موجودی، FIFO/میانگین و انطباق مقررات نیازمند تصمیم و آزمون جدا هستند.

## روش اجرا با حفظ اطلاعات قبلی

از دیتابیس پشتیبان بگیر. `docker compose down -v` اجرا نکن. فایل `.env` فعلی را در ریشه کنار `docker-compose.yml` حفظ کن. سورس را جایگزین و اجرا کن:

```bash
# در پوشه ریشه پروژه
docker compose up -d --build --force-recreate
docker compose logs --tail=100 backend
```

API هنگام شروع جدول افزوده `os_accounting_drafts` را از مدل SQLAlchemy ایجاد می‌کند. در این نسخه **Migration صریح Alembic** تعریف نشده است؛ پیش از استفاده عملیاتی نسخه‌بندی مهاجرت‌ها را تکمیل کن. هیچ جدول قبلی عمداً حذف یا بازنویسی نشده است.

با مدیر یا حسابدار وارد شو و از منوی «مالی و حسابداری ← حسابداری و امور مالی» یکی از پنج مقصد را انتخاب کن. سایر کارمندان نباید فهرست خصوصی مالی یا API `/api/v2/accounting/preparations` را ببینند.

## APIهای جدید

`GET /api/v2/accounting/preparations?kind=...`، `POST /api/v2/accounting/preparations`، `PATCH /api/v2/accounting/preparations/{id}`، `DELETE /api/v2/accounting/preparations/{id}`. تمامی این APIها صرفاً برای اطلاعات مقدماتی **غیرقطعی** هستند. فیلدها محدود و نوع داده اعتبارسنجی می‌شود. ذخیرهٔ گذرواژه، شماره کارت یا مدرک هویتی در آن‌ها ممنوع است.

## آزمون‌های انجام‌شده و باقی‌مانده

اجرای pytest روی ۴۶ تست موفق (شامل سه تست جدید مجوز کارمند، جداسازی سازمانی، عدم اثر مالی و اعتبارسنجی)؛ بررسی نحوی فایل‌های TypeScript با parser نسخه نصب‌شده و ساختار فایل‌ها انجام شد. نصب وابستگی‌های npm از این محیط به علت خطای DNS ممکن نبود، پس **Build نهایی Next.js، تست کلیک و رندر مرورگر اپلیکیشن به‌صورت واقعی هنوز تأیید نشده‌اند**.

## قبل از استفاده واقعی مالی

- مهاجرت‌ها، پشتیبان و بازیابی واقعی، ثبت‌های اتمیک و idempotency، RBAC سطری و CSRF تأیید شوند.
- مبالغ دقیق و گردش اسناد با دادهٔ تست واقعی و حسابدار متخصص بازبینی شود.
- فرایندهای مالیاتی و قوانین لازم برای محل فعالیت و سال مالی بررسی شوند.
- فقط بعد از تکمیل تست‌های سند T01 تا T21 در گزارش مرجع، عملیات مالی واقعی فعال شود.
