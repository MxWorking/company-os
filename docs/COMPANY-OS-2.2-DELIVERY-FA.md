# Company OS 2.2: تحویل نسخهٔ بازبینی امنیت و منابع انسانی

تاریخ تهیه: ۲۰۲۶-۱۰-۱۲ | وضعیت: Review Candidate، نه Production-ready

## آنچه واقعاً پیاده‌سازی شده

1. **قفل ورود:** ویترین ورود به‌صورت یک نمای عمومی مجزا نمایش داده می‌شود؛ تا وقتی `GET /api/v2/me` یک نشست معتبر برنگرداند، اپلیکیشن و سایدبار به DOM اضافه نمی‌شوند. اسکرول به محیط مدیریت دیگر راه ورود نیست. ورود فقط با حساب ساخته‌شده در API نسخه ۲ صورت می‌گیرد؛ Login نسخهٔ ۱ با HTTP 410 بسته شده است. خروج نشست را در سرور پاک می‌کند.
2. **حساب و دسترسی:** مدیر اولیه از متغیرهای محیطی اختصاصی ساخته می‌شود، نه رمز پیش‌فرض. مدیر می‌تواند برای همکاران حساب کاربری، نقش و مجوز مشخص هر ماژول را تعیین کند. سایدبار برای کارمند بر اساس مجوزهای برگردانده‌شده توسط API فیلتر می‌شود؛ کنترل نهایی مستقل در سرور انجام می‌شود. صفحه حساب شامل تغییر نام، رمز و مجوزهاست.
3. **منابع انسانی واحد:** «فهرست پرسنل قدیمی» از منوی اصلی حذف و با صفحهٔ «منابع انسانی و پرسنل» ادغام شده است. فهرست جدید با حساب عضو سازمان متصل است و امکان درج کد پرسنلی، شغل، واحد، نوع همکاری، وضعیت، زمان شروع، شماره و ایمیل کاری را فراهم می‌کند. «قرارداد و مرخصی» در همان گروه منوی سازمان قابل دسترس است.
4. **اسناد واقعیِ واردشده توسط مدیر:** عکس‌های کارت ملی جلو/پشت، شناسنامه و PDF یا تصویر مجاز توسط فرم انتخاب فایل ارسال می‌شوند. خود **فایل با AES-GCM** رمزنگاری و در جدول اختصاصی ذخیره می‌شود. فیلدهای کد ملی و موبایل نیز رمزنگاری می‌شوند؛ کد ملی از نظر کنترل‌رقم و موبایل از نظر فرمت بررسی می‌شوند. اطلاعات بیشتر شامل نام قانونی، نام پدر، تاریخ/محل تولد، شماره/سریال شناسنامه، محل صدور، کد پستی و نشانی نیز با رمزنگاری جدا ذخیره می‌شوند. فهرست عمومی کارکنان هیچ‌کدام از فیلدهای رمزنگاری‌شده را برنمی‌گرداند.
5. **پشتیبانی داخلی و سایت:** مدیر می‌تواند چند شماره تماس، ایمیل، تلگرام، واتساپ، ایتا، اینستاگرام، روبیکا یا نشانی سایت با عنوان دلخواه ثبت کند؛ کارکنان با آیکون و لینک مستقیم آن‌ها را می‌بینند. لینک‌ها باید HTTPS باشند، و هیچ شماره یا حساب ساختگی به‌صورت پیش‌فرض وجود ندارد. تیکت پشتیبانی همچنان داخلی و بدون ارسال خودکار است.
6. **سایر ویژگی‌های نسخه قبل:** پروژه‌ها، کانبان و وظایف، همکاری، یادداشت‌های خصوصی، گزارش‌ها و هسته حسابداری نسخهٔ ۲.۱ حفظ شده‌اند.

## مرز امنیتی و محدودیت‌ها

- **این نسخه برای بارگذاری اسناد هویتی واقعی در محیط اینترنت هنوز آماده نیست.** آزمون نفوذ، بررسی بدافزار روی PDF/تصاویر، سیاست نگهداری و حذف داده، مدیریت و چرخش کلید، پشتیبان رمزنگاری‌شده، لاگ مانیتورینگ و کنترل‌های قانونی/حریم خصوصی باید قبل از بهره‌برداری عملی تکمیل شوند.
- **اعتبارسنجی ≠ احراز هویت واقعی.** کد ملی تنها از نظر ساختار/کنترل‌رقم بررسی می‌شود. اعتبار واقعی سند، تعلق کارت ملی به شخص و مالکیت شماره همراه تأیید نمی‌شود. API تأیید OTP فعلاً HTTP 501 برمی‌گرداند و برچسب `phone_verified=false` تا اتصال سرویس معتبر باقی می‌ماند.
- **مهاجرت داده قدیمی:** پرونده‌های موجود در جدول `employees` نسخهٔ ۱ پاک نمی‌شوند؛ اتصال و انتقال آن‌ها به حساب‌های جدید به تأیید مدیر و تطبیق صحیح اشخاص نیاز دارد. فهرست جدید و قدیمی بدون تطبیق خودکار یکی نمی‌شوند.
- **مجوزهای نسخه ۱:** مسیرهای قدیمی فقط برای مدیر سازمان اصلی فعال‌اند و به CSRF نیاز دارند؛ بخش قابل توسعه آینده باید روی API جدید باشد.
- **Database:** جدول‌های جدید با `create_all` ساخته می‌شوند؛ مهاجرت‌های رسمی Alembic و فرآیند بکاپ/بازیابی هنوز مورد نیاز است.
- **تماس‌ها:** لینک‌های شبکه اجتماعی برای بازکردن سرویس مقصد هستند، نه چت متصل به API آن سرویس. شماره‌ها تنها پس از ثبت مدیر نمایان می‌شوند.
- **پرداخت، سرویس پیامک و دسترسی VPN/ایران:** انتخاب و پیکربندی خدمات خارجی/ایرانی و آزمون تأخیر/دسترس‌پذیری همچنان لازم است.
- **Next.js build:** دسترسی به npm در محیط ساخت برقرار نشد؛ موفقیت Build واقعی و آزمون بصریِ اپلیکیشن تأیید نشده است.

## راه‌اندازی با Docker

در پوشهٔ اصلی پروژه یک فایل `.env` بسازید (آن را در Git ثبت نکنید):

```env
ADMIN_USERNAME=company-owner
ADMIN_PASSWORD=replace-with-a-unique-long-password
SESSION_SECRET=replace-with-a-random-64-character-value
HR_ENCRYPTION_KEY=replace-with-64-hex-digits
```

کلیدها را در سیستم خودتان تولید کنید:

```bash
python -c "import secrets; print('SESSION_SECRET='+secrets.token_urlsafe(48)); print('HR_ENCRYPTION_KEY='+secrets.token_hex(32))"
```

با گذرواژه‌ای تصادفی و طولانی به‌جای عبارت نمونه، سپس اجرا:

```bash
docker compose up --build
```

- Frontend: `http://localhost:3000`
- Backend health: `http://localhost:8000/health`
- با نام کاربری/رمز مدیر که خودتان در `.env` ساخته‌اید، از ویترین وارد شوید. **هرگز `DEMO_MODE=true` را برای سرور عمومی یا استفاده واقعی فعال نکنید.**
- حساب‌های اعضا در «سازمان ← منابع انسانی ← حساب‌های اعضا» ساخته می‌شوند. مجوزها در «حساب و دسترسی‌ها» تعیین می‌شوند.
- بدون مقدار صحیح `HR_ENCRYPTION_KEY`، ثبت و مشاهده مدارک هویتی با خطای 503 متوقف می‌شود. با گم‌شدن کلید، بازیابی اطلاعات رمزنگاری‌شده ممکن نخواهد بود.

## وضعیت تست‌های قابل گزارش

- `python -m pytest -q`: **۳۴ تست پاس شد**؛ تست‌های جدید ورود امن، جداسازی دسترسی کارکنان، مدارک رمزنگاری‌شده و تماس پشتیبانی را پوشش می‌دهند.
- `typescript.transpileModule`: نحو **۱۲ فایل TS/TSX** بدون خطای نحوی بررسی شد. این بررسی جایگزین Typecheck واقعی با پکیج‌های نصب‌شده نیست.
- انتشار در GitHub و Vercel انجام نشده است.
