# Company OS 2.1 — گزارش تحویل، روش تست و محدودیت‌ها

> نوع انتشار: **Integration Review / Security-sensitive Prototype**. این ZIP برای تست محلی است و هنوز برای نگهداری داده‌های واقعی سازمان، مدارک هویتی یا دفاتر مالی در Production تأیید نشده است.
>
> هیچ Push به GitHub و هیچ Deploy به Vercel انجام نشده است.

## تغییرات قابل استفاده در سورس

### ناوبری / سطح دسترسی
- سایدبار جدید گروه‌بندی‌شده، زیرمنوهای باز/بسته‌شونده و حذف آیتم‌های تکراری منوی اصلی.
- «وظایف من» زیر مجموعه «وظایف»؛ پروژه‌ها، سازمان، ارتباطات، مالی، گزارش‌ها و حساب/پشتیبانی گروه‌های مستقل دارند.
- حساب‌های عضو سازمان با نام کاربری و رمز عبور و نقش‌های owner/admin/manager/member/viewer از 2.0 حفظ شده‌اند.
- مجوزهای جزئی برای خواندن/نوشتن هر ماژول در جدول `os_module_grants` ذخیره می‌شوند؛ فقط owner/admin مجاز به تغییرشان هستند.
- بخش‌های غیرمجاز در منو پنهان‌اند و API به‌صورت مستقل آن‌ها را بررسی می‌کند. رکوردهای پروژه و وظیفه برای اعضا به فهرست پروژه‌های واگذارشده/وظایف مجاز محدود شده‌اند.
- امکان ویرایش نام و تغییر رمز با تأیید رمز قبلی. بازیابی رمز عبور، ابطال همه نشست‌ها و MFA **هنوز وجود ندارند**.

### فضای اختصاصی هر پروژه
- فهرست پروژه‌ها و صفحه Project Workspace با تب‌های Overview، وظایف، گفتگو/گزارش روزانه، تقویم، اعضا/تیم‌ها، یادداشت خصوصی، درخواست تأیید.
- دعوت حساب‌های سازمان به هر پروژه و انتساب چند تیم؛ اعضای فاقد عضویت مجاز به دیدن چت و رویدادهای آن نیستند.
- گفتگوهای متنی و انواع «گزارش روزانه»، «درخواست تغییر»، «تصمیم مدیر» و «اطلاعیه».
- درخواست‌های تأیید پروژه با وضعیت `pending/approved/rejected`، ثبت تصمیم مدیر و تاریخچه Audit.
- رویدادهای تاریخ‌دار شامل خرید، تحویل، جلسه و ددلاین. تقویم ماهانه روی فرانت‌اند نمایش می‌یابد؛ **موتور زمان‌بندی خودکار و یادآور زمان‌بندی‌شده در این نسخه نیست**.
- ارتباط یک پروژه با مشتری ثبت‌شده، وظایف محول‌شده و یادداشت‌های خصوصی هر کاربر در همان پروژه.
- گفتگوی عمومی سازمان خارج از پروژه و تیکت‌های پشتیبانی داخلی/توسعه‌دهنده.
- گفتگو با REST و Refresh دستی است؛ نه پیام‌رسان WebSocket بلادرنگ؛ تماس صوتی/تصویری داخلی پیاده‌سازی نشده. می‌توان URL جلسه خارجی را به رکورد `meeting` الصاق کرد.

### منابع انسانی و اطلاعات حساس
- پرونده‌های پرسنلی نسخه قبل حفظ شده‌اند؛ ماژول جداگانه Vault برای ذخیره **رمزنگاری‌شده** کد ملی و شماره تلفن و فایل‌های JPEG/PNG/PDF با حداکثر ۵ مگابایت ایجاد شده.
- **حتماً** `HR_ENCRYPTION_KEY` با ۶۴ کاراکتر hex تنظیم شود؛ بدون آن API ذخیره/خواندن داده هویتی `503` برمی‌گرداند. فایل‌ها به‌صورت ciphertext در دیتابیس قرار می‌گیرند.
- کنترل رقم کد ملی فقط **اعتبارسنجی الگوریتمی** است، نه احراز هویت رسمی ثبت‌احوال. همچنین بدون سرویس پیامک واقعی، شماره موبایل همیشه `phone_verified=false` می‌ماند و درخواست OTP `501` است.
- این یک Vault آزمایشی است: هنوز اسکن ویروس، پاک‌سازی محتوای سند، سیاست حذف/رضایت، زمان انقضا و ممیزی امنیت رسمی ندارد. برای داده واقعی کارکنان در اینترنت مناسب نیست.

### مالی و حسابداری
- ماژول Ledger واقعیِ پایه و جدا از ثبت فاکتور/هزینه‌های MVP پیشین.
- تعریف کدینگ حساب با گروه asset / liability / equity / revenue / expense.
- ثبت سند حداقل دو ردیفی با مبالغ **عدد صحیح ریال** و کنترل تساوی بدهکار و بستانکار؛ ثبت پیش‌نویس، قطعی کردن سند، جلوگیری از قطعی‌کردن دوباره و قفل‌کردن ماه مالی.
- تراز آزمایشی بر اساس اسناد قطعی، جمع بدهکار/بستانکار و سود/زیان ساده حساب‌های درآمد و هزینه.
- این **جایگزین کامل هلو/محصولات حسابداری شرکتی نیست**: هنوز دفاتر رسمی، سطوح شناور/تفصیلی، مالیات، ارزش افزوده، کالا/انبار، حقوق‌ودستمزد، خزانه‌داری و بانک/چک، ثبت اصلاحی/بستن سال، چندارزی واقعی، اتصال سامانه مودیان، گزارش قانونی و کنترل‌های ممیزی لازم را ندارد.

### پشتیبانی و دانش‌نامه
- به جای تب مستقل دانش‌نامه، توضیح و راهنمای آن در «راهنما و پشتیبانی» قرار گرفته. دانش‌نامه برای سیاست‌ها، راهنمای کارمندان، SOPها، الگوها و FAQهای سازمانی مفید است.
- تیکت‌های «پشتیبانی داخلی» و «توسعه‌دهنده» در دیتابیس سازمان ذخیره می‌شوند. **ارسال خودکار ایمیل/پیامک هنوز نیست.**
- اطلاعات تماس اختیاری از `DEVELOPER_SUPPORT_EMAIL` و `INTERNAL_SUPPORT_CONTACT` خوانده می‌شود، نه شماره جعلی.

## راه‌اندازی محلی

### 1) بک‌اند

```bash
cd backend
python -m venv .venv
# Windows: .venv\Scripts\Activate.ps1
# Linux: source .venv/bin/activate
pip install -r requirements.txt -r requirements-dev.txt
# APP_ENV=development DEMO_MODE=true فقط برای تست
# برای تست vault یک کلید ثابت 32 بایتی hex بسازید:
python -c "import secrets; print(secrets.token_hex(32))"
# نتیجه را به HR_ENCRYPTION_KEY در محیط توسعه وارد کنید و از انتشار آن خودداری کنید
uvicorn main:app --reload --port 8000
python -m pytest -q
```

در محیط واقعی، `APP_ENV=production`, `DEMO_MODE=false`, `SESSION_SECRET` قوی و `ADMIN_PASSWORD` باید تنظیم شوند. PostgreSQL الزامی است. **از این نسخه بدون بازبینی امنیت در اینترنت استفاده نکنید.**

### 2) فرانت‌اند

```bash
cd frontend
npm install
npm run dev
npm run typecheck
npm run build
```

آدرس `http://localhost:3000`، مستند API در `http://localhost:8000/docs`.

برای ورود اعضا: مدیر از بخش «سازمان و اعضا» عضو جدید با username و password می‌سازد؛ کاربر با همان اطلاعات وارد می‌شود؛ مدیر از «حساب و دسترسی‌ها» مجوز اختصاصی می‌دهد.

## تست‌های انجام شده

- اجرای واقعی `python -m pytest -q`: **۳۲ تست موفق** در این محیط؛ APIهای پایه و افزوده، مجوز، جداسازی سازمان، ثبت حسابداری، اسناد هویتی آزمایشی و ثبت تصمیم پروژه.
- بررسی نحوی فایل‌های TS/TSX با TypeScript `transpileModule`، و تجزیه CSS با `tinycss2`: بدون خطای نحوی.
- **تست Next.js production build، تایپ‌چک کامل با type declarations و تست مرورگری UI انجام نشده** چون وابستگی‌های npm در این محیط موجود نیستند. قبل از انتشار ضروری است.
- هنوز Alembic migration قابل اتکا، تست نفوذ، رمزگذاری secrets در KMS، تست فشار، پشتیبان‌گیری بازیابی‌شده، محدودسازی نرخ ورود، ثبت سیاست حریم خصوصی و طرح حذف قانونی اطلاعات وجود ندارد.

## فازهای تکمیلی پیشنهادی بعد از تست این ZIP

1. فاز امنیت و استقرار: واقعی‌سازی RBAC بر اساس نقش/پروژه، کنترل‌های شیءبه‌شیء در کل سیستم، MFA، ریکاوری، OTP واقعی و مدیریت Secure Session، مهاجرت‌های Alembic.
2. فاز همکاری: چت بلادرنگ، اعلان‌ها، امضای الکترونیکی با ارائه‌دهنده مناسب، آپلود امن فایل عمومی و ویدیوکنفرانس با یک سرویس تأییدشده.
3. فاز ERP مالی: حسابداری چندسطحی، انبار/خرید، خزانه، حقوق و دستمزد، مالیات/مودیان و انواع گزارش‌های قانونی متناسب با الزامات ایران، با بازبینی حسابدار حرفه‌ای.
4. تست کیفیت: QA دستی UI در دو تم، دو زبان و چند اندازه، Build فرانت‌اند، تست مجوز و تست امنیتی پیش از اتصال دیتای واقعی.
